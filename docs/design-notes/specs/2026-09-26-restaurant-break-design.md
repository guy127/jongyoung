# ช่วงพักร้าน (เปิด 2 ช่วงเวลา) — design

## ที่มา
บางร้านเปิดสองช่วง เช่น กลางวัน 11:00–14:00 และเย็น 17:00–22:00
เลือกทำเป็น **"ช่วงพัก 1 ช่วงภายในรอบเดียว"** (11:00–22:00 พัก 14:00–17:00) แทนตารางหลายช่วง
เพราะนิยามวันทำการ (`Window`, `At`, `BusinessDate`) ไม่ต้องเปลี่ยนเลย และอธิบายได้ในประโยคเดียว:
"ร้านมีรอบเดียว มีช่วงพักตรงกลางได้หนึ่งช่วง"

ทางที่ไม่เลือก:
- ตาราง `restaurant_hours` หลายช่วง/ต่อวัน — ครอบทุกเคสแต่ต้องเขียน businessday ใหม่ทั้งชุด เสี่ยงเกินเวลาที่เหลือ
- ไม่รองรับเลย — ร้านที่มีพักต้องตั้งเวลาเปิดยาวแล้วรับจองช่วงพัก

## 1. ข้อมูล
migration `00007_add_break.sql` (Up + Down):
```sql
ALTER TABLE restaurants
    ADD COLUMN break_start_minute int NOT NULL DEFAULT 0 CHECK (break_start_minute BETWEEN 0 AND 1439),
    ADD COLUMN break_end_minute   int NOT NULL DEFAULT 0 CHECK (break_end_minute BETWEEN 0 AND 1439);
```
- `break_start_minute == break_end_minute` = **ไม่มีช่วงพัก** (ไม่ใช้ NULL → Go ไม่ต้องใช้ pointer และ `Hours` ยังเทียบด้วย `!=` ได้)
- ช่วงพักใช้ทุกวันทำการ ไม่แยกตามวันในสัปดาห์
- ช่วงพักต้องอยู่ **ข้างในรอบจริง ๆ**: นับเป็นนาทีจากเวลาเปิด `0 < offset(start) < offset(end) < duration`
  (ติดขอบรอบ = แค่ย่นเวลาเปิด ให้ไปแก้เวลาเปิด–ปิดแทน) — วิธีนับ offset เดียวกับ `Fits` จึงใช้กับร้านข้ามคืนได้ (เช่น 18:00–02:00 พัก 23:00–00:00)
  ผิด → 400 `INVALID_BREAK`

## 2. กติกา — อยู่ใน `businessday.go` ที่เดียว
- `Hours` เพิ่ม `BreakStartMinute`, `BreakEndMinute`
- `HasBreak()` และ `Break(date) (start, end time.Time, ok bool)` = `opensAt + offset` ของรอบวันทำการ `date`
- `ValidBreak()` ตรวจเงื่อนไขข้อ 1 (ใช้ตอนรับ input ของร้าน)
- `Fits(start, end)` เพิ่มเงื่อนไข: ช่วงจองต้องไม่ทับช่วงพักของรอบนั้น (`start < breakEnd && end > breakStart` = ไม่ผ่าน)
  จองจบ 14:00 พอดี / เริ่ม 17:00 พอดี = ผ่าน; ร้าน 24 ชม. ที่คร่อมเข้ารอบถัดไป ตรวจช่วงพักของรอบถัดไปด้วย
- `Slots` (availability, next-available, บอร์ด owner) **ข้าม** ช่วงที่ทับช่วงพัก เหมือนตัดช่วงที่เลย lead time

ได้มาเองโดยไม่ต้องเขียนเพิ่ม (เพราะทุกที่เรียก `Fits`/`Slots` ตัวเดียวกัน):
- POST / PUT `/bookings` ทับช่วงพัก → 400 (ข้อ 5 ของ 5.2)
- ปุ่มเวลาบนการ์ด (`SlotsAround`) → `closed: true`
- ตั้งช่วงพักทับ booking ในอนาคต → `CheckHoursChange` → 409 `HOURS_CONFLICT_EXISTING_BOOKINGS`
  (service ตรวจเมื่อ `in.Hours() != rest.Hours()` ซึ่งตอนนี้รวมช่วงพักแล้ว)

## 3. API
- request (`RestaurantRequest`): `break_start`, `break_end` เป็น `"HH:MM"` ไม่บังคับ ลง :00/:30 — ส่งคู่หรือไม่ส่งเลย; มีตัวเดียว → 400 `INVALID_BREAK`
- response (`RestaurantResponse`): `break_start`, `break_end` เป็น `""` เมื่อไม่มีช่วงพัก (แบบเดียวกับ `map_url`)
- availability / บอร์ด owner ไม่เปลี่ยนรูปแบบ — ช่วงพักคือ "ช่องว่าง" ระหว่าง slot สองตัวที่ `end_at` ไม่ต่อกับ `start_at` ถัดไป

## 4. Web
- ฟอร์มร้าน: input เวลา 2 ช่อง (ไม่บังคับ) + zod ตรวจว่ากรอกคู่
- ป้ายเวลาเปิด (การ์ด, หน้าร้าน, ตาราง owner): `11:00–22:00 · พัก 14:00–17:00` — ทำเป็นฟังก์ชันเดียวใน `lib/format.ts`
- แผงจอง: ตรงที่ slot ไม่ต่อกัน แสดงเส้นแบ่ง "พักร้าน 14:00–17:00"
- บอร์ด owner: ตรงที่ slot ไม่ต่อกัน แสดงแถว "พักร้าน" แทน seat bar

## 5. Seed
`ซูชิ ทาคุมิ` (11:00–22:00) ตั้งช่วงพัก 15:00–17:00 ด้วย `UPDATE` แบบเดียวกับ `closed_weekdays` ของร้านบุฟเฟ่ต์
booking ของร้านนี้ใน seed คือ 19:00–20:30 → ไม่ทับช่วงพัก

## 6. Test (เขียนก่อน)
`businessday_test.go`
- ร้าน 11:00–22:00 พัก 14:00–17:00: จบ 14:00 พอดี ผ่าน / 13:30–14:30 ไม่ผ่าน / 14:30–15:00 ไม่ผ่าน / 13:00–18:00 (ครอบทั้งพัก) ไม่ผ่าน / เริ่ม 17:00 ผ่าน
- ร้าน 18:00–02:00 พัก 23:00–00:00: 23:30 ไม่ผ่าน, 00:00–01:00 ผ่าน
- ร้าน 24 ชม. พัก 03:00–05:00: คร่อมเที่ยงคืนเข้ารอบถัดไปแล้วทับพักของรอบถัดไป → ไม่ผ่าน
- `ValidBreak`: ไม่มีพัก ผ่าน / ติดขอบเปิด / ติดขอบปิด / อยู่นอกรอบ / start หลัง end → ไม่ผ่าน
